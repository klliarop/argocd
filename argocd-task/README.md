# ArgoCD Pull Secret Rotation

GitOps-based automation for rotating the OpenShift global pull secret across multiple clusters
(UAT → PLD → DR) using **ArgoCD** + **Sealed Secrets**.

---

## Two commands. That's it.

### First time only (per cluster):
```bash
oc login <cluster-api-url>
./scripts/bootstrap-cluster.sh uat
```

### Every rotation after that:
```bash
oc login <cluster-api-url>
./scripts/rotate-pull-secret.sh uat ./new-pull-secret.json
git add gitops/overlays/uat/sealed-secret.yaml
git commit -m "chore: rotate pull secret for UAT"
git push
# ArgoCD propagates the change to the cluster automatically
```

Repeat for `pld` and `dr`.

---

## What each script does

### `bootstrap-cluster.sh <env>` — run once per cluster, ever
| Step | What happens |
|------|-------------|
| 1 | Confirms you are logged in to the right cluster |
| 2 | Installs `kubeseal` CLI on your VDI if missing |
| 3 | Installs the Sealed Secrets **controller** on the cluster via Helm (skips if already there) |
| 4 | Backs up the current pull secret |
| 5 | Registers the ArgoCD Application so ArgoCD starts watching this repo |

### `rotate-pull-secret.sh <env> <new-pull-secret.json>` — run every rotation
| Step | What happens |
|------|-------------|
| 1 | Backs up the current pull secret from the cluster with a timestamp |
| 2 | Validates the new secret with a real `podman pull` test |
| 3 | Merges the new Red Hat credentials with existing ones (`cp.icr.io`, `us.icr.io`, etc.) |
| 4 | Encrypts the merged secret with the cluster's public key → writes `sealed-secret.yaml` |

---

## Where things run

```
YOUR VDI                          CLUSTER
────────────────────────────────  ──────────────────────────────────────
oc login                          (receives oc commands)
./scripts/bootstrap-cluster.sh   → installs Sealed Secrets controller pod
./scripts/rotate-pull-secret.sh  → fetches public key, writes sealed-secret.yaml locally
git push                          (ArgoCD watches GitHub)
                                  ArgoCD applies sealed-secret.yaml
                                  Sealed Secrets controller decrypts it
                                  openshift-config/pull-secret updated ✓
```

**Nothing runs directly on the cluster nodes.** Everything goes through `oc` from your VDI.

---

## Do nodes restart after the update?

**No.** As of OpenShift 4.7.4+, updating the global pull secret does not reboot nodes.
The MCO restarts only the `crio` service. You will see `MachineConfigPool` briefly show
`UPDATING=True` — wait for it to return to `UPDATED=True`. Running workloads are unaffected.

---

## Different registries per cluster — handled automatically

Each cluster may have different registry credentials today (e.g. one cluster has a custom registry
the others don't). The rotation script detects this automatically:

- It reads the **current** cluster's pull secret
- Merges the new Red Hat creds with whatever registries are already there
- Warns you if any registry is about to be lost
- Each `sealed-secret.yaml` is encrypted specifically for that cluster — one cluster's sealed file
  cannot be decrypted by another cluster

## Before first use — edit the ArgoCD app manifests

Open each file and replace the two `TODO` placeholders:

```yaml
# argocd/app-uat.yaml  (same pattern for pld and dr)
source:
  repoURL: https://github.com/<your-org>/<your-repo>.git   # ← your GitHub repo
destination:
  server: https://api.uat-cluster.example.com:6443          # ← your cluster API URL
```

Then commit and push this repo to GitHub before running `bootstrap-cluster.sh`.

## Rollback

```bash
# Restore directly from backup (immediate, bypasses ArgoCD)
oc set data secret/pull-secret \
  -n openshift-config \
  --from-file=.dockerconfigjson=./backups/pull-secret-uat-<timestamp>.json

# Re-seal the backup so Git matches the cluster again
./scripts/rotate-pull-secret.sh uat ./backups/pull-secret-uat-<timestamp>.json
git add gitops/overlays/uat/sealed-secret.yaml
git commit -m "revert: restore pull secret backup for UAT"
git push
```
